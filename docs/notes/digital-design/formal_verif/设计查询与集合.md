# 设计查询、对象集合与属性筛选

## 1. 查询对象不是修改 RTL

VC Formal 展开设计后，脚本使用带有类型的对象表示设计、实例、端口、引脚和网络。查询命令返回对象集合；集合中的成员指向展开模型，而不是从源代码截取出的文字。筛选和排序只改变后续脚本使用的对象范围，不会修改寄存器、电路连接或模块参数。

| 对象类别 | 表示什么 | 常见查询 |
| --- | --- | --- |
| design | 模块或库设计定义 | `get_designs` |
| cell | 展开后的实例 | `get_cells` |
| port | 当前顶层的输入输出端口 | `get_ports` |
| pin | 实例上的接口引脚 | `get_pins` |
| net | 连接驱动端与接收端的网络 | `get_nets` |
| lib_cell、lib_pin | 库单元及其引脚定义 | `get_lib_cells`、`get_lib_pins` |

例如两个计数器实例可以引用同一个模块定义，但分别具有不同的层次路径、复位连接和内部状态。查询 `design` 只能确定模块定义；给某个实例施加黑盒或追踪某条信号的影响范围，通常需要实例或网络对象。把对象类别选错，常见结果是查询为空或后续命令拒绝该集合，而不是设计中真的没有这段逻辑。

## 2. 名称、集合与 Tcl 列表

普通 Tcl 列表保存字符串等值，对象集合保存工具管理的设计对象。`get_object_name` 用于输出可读名称，`sizeof_collection` 用于计数，`foreach_in_collection` 用于逐对象遍历。不要用 `llength` 判断对象数量，也不要把 `query_objects` 的打印结果当作集合返回值。

模式查询通常使用星号和问号；准确匹配含特殊字符的名称时，既要处理查询规则，也要处理 Tcl 的求值规则。花括号可避免 Tcl 提前解释美元符号、方括号和反斜杠。正则表达式模式与普通通配符不是同一语法，是否启用正则模式应保持显式一致。

```tcl
set cells [get_cells -hierarchical *]
puts "对象数：[sizeof_collection $cells]"
foreach_in_collection cell $cells {
    puts [get_object_name $cell]
}
```

层次查询还要区分“逐层匹配叶名”和“指定完整路径”。脚本应在应用约束或生成检查之前打印命中数量及少量对象名称；本来应有几千个对象却只命中零个，必须作为设置问题停止处理，不能继续产生一份看似通过的空报告。

以下命令覆盖 UG 附录 A 中的基本查询、集合操作和属性访问。UG 对部分查询只介绍作用，没有给出完整平台选项；这些条目仅列出能够核实的基本形式。详细示例都以已完成设计展开为前提。

### 3.1 `get_command_option_values`：读取命令的默认参数和最近参数

```text
get_command_option_values [-default] [-current] -command <command>
```

**参数解释。** `-command` 指定命令名称；`-default` 读取已登记的默认值，`-current` 读取最近使用的值。两个选项均未写出时，优先返回当前值，没有当前值时使用默认值。返回值是“参数名、参数值”交替排列的 Tcl 列表，可以交给 `array set`。

**用法与结果。** 该查询适合把交互操作中的选项保存到脚本中，但不是所有命令都会登记全部选项。返回空列表只表示没有可查询的记录，不能据此判断命令不支持参数。读取参数不会重新执行原命令。

```tcl
set opts [get_command_option_values -current -command report_fv]
array set report_options $opts
parray report_options
```

来源：User Guide，X-2025.06-SP1，第 1085–1086 页。

### 3.2 `get_cells`：按名称、层次和属性查询实例

```text
get_cells [-hierarchical] [-quiet] [-regexp] [-nocase] [-exact]
          [-filter <expression>] <patterns>
get_cells [-quiet] [-filter <expression>] -of_objects <objects>
```

**参数解释。** `<patterns>` 是实例名称或模式组成的 Tcl 列表；`-hierarchical` 搜索层次中的实例；`-quiet` 抑制未匹配对象的提示。`-regexp` 使用正则表达式，`-exact` 将模式作为准确名称，两者互斥；`-nocase` 忽略大小写。`-filter` 对匹配实例继续进行属性筛选。`-of_objects` 从给定对象取得所属实例，不与名称模式同时使用。

**用法与结果。** 返回的是实例对象集合，不是模块定义名组成的字符串列表。用 `get_object_name` 取得可打印名称，用 `foreach_in_collection` 遍历对象。名称模式决定先搜索哪些实例，属性表达式决定哪些实例最终保留，因此名称查询为空和属性筛选为空应分开排查。

```tcl
set regs [get_cells -hierarchical * -filter {is_sequential == true}]
puts "实例数：[sizeof_collection $regs]"
foreach_in_collection cell $regs {
    puts [get_object_name $cell]
}
```

来源：User Guide，X-2025.06-SP1，第 1085–1088、1091–1094 页。

### 3.3 `get_designs`：查询设计定义

```text
get_designs <patterns>
```

**参数解释。** `<patterns>` 指定对象名称或匹配模式。这里列出 UG 介绍的基本查询形式；各对象类型的其他选项由 VC Static Platform 命令参考定义，不把 `get_cells` 的全部选项机械套用到这些命令。

**用法与结果。** 查询已经读入并展开的设计定义，而不是某个层次下的实例。多个实例可以引用同一个设计定义。 返回值是对象集合，可用于后续筛选、属性读取或计数。先检查集合是否为空，再对具体对象执行需要非空输入的操作。

```tcl
set designs [get_designs *]
query_objects $designs
```

### 3.4 `get_ports`：查询顶层端口

```tcl
set ports [get_ports *]
foreach_in_collection p $ports {
    puts "[get_object_name $p] [get_attribute $p direction]"
}
```

### 3.9 `get_object_name`：把对象转换成可读名称

```text
get_object_name <objects>
```

**参数解释。** `<objects>` 是对象或对象集合，返回相应对象名称。名称适合打印、保存到文本或构造报告，但不能代替对象集合完成所有集合运算。

**用法与结果。** 集合在 Tcl 中以句柄表示。直接 `puts $objects` 可能打印句柄，而不是用户想要的实例路径。为了保持对象类型和属性，内部计算保留集合，只在输出时转换名称。

```tcl
set cells [get_cells *]
puts [get_object_name $cells]
```

来源：User Guide，X-2025.06-SP1，第 1083、1089–1090 页。

### 3.10 `query_objects`：显示集合中的对象

```text
query_objects <collection>
query_objects [-verbose] -class <class> <pattern>
```

**参数解释。** `<collection>` 是待显示集合；`-class` 选择对象类别，`<pattern>` 指定名称模式；`-verbose` 可显示类别信息，便于辨别混合了端口、引脚等对象的集合。

**用法与结果。** 该命令将对象打印到控制台，但返回空字符串。因此不要用 `set x [query_objects $cells]` 保存查询结果；这样得到的 `x` 不是原集合。需要保存集合时直接保存 `get_cells` 等查询的返回值。

```tcl
set p [get_ports *]
query_objects $p
query_objects -class port *
```

来源：User Guide，X-2025.06-SP1，第 1089–1090、1097 页。

### 3.11 `filter_collection`：按属性筛选已有集合

```text
filter_collection <collection> <expression> [-regexp] [-nocase]
```

**参数解释。** `<expression>` 是对象属性表达式。`-regexp` 让名称匹配使用正则表达式；`-nocase` 忽略大小写。筛选产生新集合，不修改输入集合。

**用法与结果。** 表达式中的属性必须适用于该对象类别。平台的复合表达式不能简单照搬其他语言的优先级假设，多个逻辑条件应显式加括号。若查询命令本身支持 `-filter`，直接查询并筛选通常比先构造大集合再筛选更合适。

```tcl
set all_cells [get_cells -hierarchical *]
set regs [filter_collection $all_cells {is_sequential == true}]
puts "全部：[sizeof_collection $all_cells]；时序实例：[sizeof_collection $regs]"
```

来源：User Guide，X-2025.06-SP1，第 1092–1095 页。

### 3.12 `foreach_in_collection`：逐对象遍历集合

```text
foreach_in_collection <iter_var> <collections> <body>
```

**参数解释。** `<iter_var>` 是循环变量名称，`<collections>` 是待遍历的集合，`<body>` 是每次执行的 Tcl 脚本。每次迭代时变量表示一个仅含当前对象的集合。

**用法与结果。** 不能把对象集合当作普通 Tcl 列表交给 `foreach`。普通 `foreach` 可能只遍历到集合句柄，后续名称和属性操作便不再对应真实对象。循环体使用花括号，使变量在每次迭代时求值。

```tcl
foreach_in_collection p [get_ports *] {
    set n [get_object_name $p]
    set d [get_attribute $p direction]
    puts "$n : $d"
}
```

来源：User Guide，X-2025.06-SP1，第 1095 页。

### 3.13 `add_to_collection`：创建加入对象后的集合

```text
add_to_collection <collection> <object_spec> [-unique]
```

**参数解释。** `<object_spec>` 可以是对象名称、模式或集合；`-unique` 用于避免重复对象。返回包含原对象及新增对象的新集合，原集合保持不变。

**用法与结果。** 添加对象不会在 RTL 中创建硬件，只改变查询结果。需要把结果保存回原变量时必须明确赋值。混合类别的集合只适合能同时接受这些类别的下游命令，不能因为加入成功便假定所有属性都通用。

```tcl
set selected [get_ports {clk rst_n}]
set selected [add_to_collection $selected [get_ports {enable}] -unique]
query_objects $selected
```

来源：User Guide，X-2025.06-SP1，第 1096–1097 页。

### 3.14 `remove_from_collection`：创建删除指定对象后的集合

```text
remove_from_collection <collection> <object_spec>
```

**参数解释。** `<object_spec>` 指定要移除的名称、模式或集合。返回剩余对象构成的新集合；若结果为空，则返回空集合表示。

**用法与结果。** 这不是删除设计对象，也不会删除端口或逻辑。它仅改变后续操作使用的对象范围。原集合不变，便于保留全集并分别构造时钟端口、控制端口和数据端口的子集。

```tcl
set all_ports [get_ports *]
set data_ports [remove_from_collection $all_ports [get_ports {clk rst_n}]]
query_objects $data_ports
```

来源：User Guide，X-2025.06-SP1，第 1096 页。

### 3.15 `sort_collection`：按一个或多个属性排序

```text
sort_collection [-descending] <collection> <criteria>
```

**参数解释。** `<criteria>` 是排序属性的有序列表，优先按第一个属性排序，值相同时再比较后续属性。默认升序；`-descending` 使用降序。布尔属性升序时 false 在 true 前面。

**用法与结果。** 排序适合生成稳定、便于版本比较的报告。对于某些对象缺失的稀疏属性，平台还有专门的缺失值排列规则；不要用排序位置推断该对象是否具备硬件特征，应读取属性本身。

```tcl
set sorted [sort_collection [get_ports *] {direction full_name}]
foreach_in_collection p $sorted {
    puts [get_object_name $p]
}
```

来源：User Guide，X-2025.06-SP1，第 1097 页。

### 3.16 `sizeof_collection`：计算集合对象数

```text
sizeof_collection <collection>
```

**参数解释。** `<collection>` 是待计数集合，返回整数。空字符串作为空集合时返回 0。

**用法与结果。** 集合计数应使用本命令，不能用 `llength` 计算句柄字符串的长度。命令返回 0 时，先检查名称、层次和筛选条件，不要把空集合直接解释为设计中不存在对应功能。

```tcl
set regs [get_cells -hierarchical * -filter {is_sequential == true}]
if {[sizeof_collection $regs] == 0} {
    error "未找到时序实例，请检查展开结果与对象属性"
}
```

来源：User Guide，X-2025.06-SP1，第 1098 页。

### 3.17 `compare_collections`：比较两个集合是否相等

```text
compare_collections <collection1> <collection2> [-order_dependent]
```

**参数解释。** 默认只比较对象成员；`-order_dependent` 同时要求排列顺序一致。返回值为 0 表示相等，非零表示不同。

**用法与结果。** 返回值并不是“1 表示相等”的布尔接口。若脚本把非零值当作相等，就会反向判断集合变化。可用于检查筛选规则变化是否改变了测试对象范围。

```tcl
set a [get_ports *]
set b [sort_collection $a full_name]
if {[compare_collections $a $b] == 0} {
    puts "成员相同，排序未改变检查范围"
}
```

来源：User Guide，X-2025.06-SP1，第 1098 页。

### 3.18 `copy_collection`：复制集合容器

```text
copy_collection <collection>
```

**参数解释。** 返回独立的集合副本。副本中的成员仍是同一设计中的对象，不复制实例、引脚或网络。

**用法与结果。** 普通 `set b $a` 复制的是集合句柄的引用。本命令适合明确要求独立集合容器的场合，但不应误认为复制后拥有第二份可以独立修改的 RTL 设计。

```tcl
set original [get_cells *]
set snapshot [copy_collection $original]
puts [sizeof_collection $snapshot]
```

来源：User Guide，X-2025.06-SP1，第 1099 页。

### 3.19 `index_collection`：按下标取得集合成员

```text
index_collection <collection> <index>
```

**参数解释。** `<index>` 从 0 开始。返回指定位置的对象集合。不是所有集合都支持按下标访问，应优先使用集合遍历。

**用法与结果。** 按位置选择对象通常不如按准确名称或属性可靠；展开或排序变化可能改变对象顺序。确需选择第一项时先检查集合非空，并在报告中打印选中对象名称。

```tcl
set ports [sort_collection [get_ports *] full_name]
if {[sizeof_collection $ports] > 0} {
    puts [get_object_name [index_collection $ports 0]]
}
```

来源：User Guide，X-2025.06-SP1，第 1099 页。

### 3.20 `get_attribute`：读取对象属性

```text
get_attribute <object> <attribute>
```

**参数解释。** `<object>` 是要查询的对象，`<attribute>` 是大小写敏感的属性名。常见属性包括 `object_class`、`full_name`、`direction`、`ref_name` 和 `is_sequential`，但并非每类对象都支持全部属性。

**用法与结果。** 对象属性描述当前展开模型，不应脱离对象类别解释。例如实例的 `ref_name` 是所引用的设计或库单元，端口的 `direction` 描述顶层接口方向。应用属性通常只读，不应尝试通过改属性代替修改 RTL 或设置验证环境。

```tcl
foreach_in_collection p [get_ports *] {
    puts "[get_attribute $p full_name] : [get_attribute $p direction]"
}
```

来源：User Guide，X-2025.06-SP1，第 1100–1105 页。

### 3.21 `list_attributes`：列出某类对象可查询的属性

```text
list_attributes -application -class <class>
```

**参数解释。** `-application` 包含工具应用定义的属性；`-class` 指定对象类别，例如 `cell`、`port`、`pin`、`net`、`design`、`lib_cell`、`lib_pin`。

**用法与结果。** 先查看属性目录，再编写筛选表达式，可以避免把其他工具或其他类别的属性直接套用过来。目录给出属性名和类型；具体对象是否具备某项属性，还应结合该对象的实际查询结果判断。

```tcl
list_attributes -application -class cell
list_attributes -application -class port
```

来源：User Guide，X-2025.06-SP1，第 1100–1101 页。

## 4. 将查询结果用于验证范围审查

在大规模工程中，查询规则本身也是需要审查的配置。先保留全集，再构造子集，并用计数和名称报告验证筛选范围。只有在确认实例类别和设计层次后，才把集合交给黑盒、连接提取或复杂度分析命令。若集合内混有不同对象类别，属性读取和下游命令必须同时支持这些类别。

```tcl
set all_cells [get_cells -hierarchical *]
set blackboxes [filter_collection $all_cells {is_black_box == true}]
puts "总实例：[sizeof_collection $all_cells]"
puts "黑盒实例：[sizeof_collection $blackboxes]"
foreach_in_collection cell $blackboxes {
    puts [get_object_name $cell]
}
```

这段脚本只报告当前模型中的黑盒实例，不证明黑盒模型正确。最终需要把实例清单与功能规格、使用的替代模型以及受其影响的属性一起审查。来源：User Guide，第 1081–1109 页。
